# Project structure, roles and capability boundaries

VibeSilicon provides FPGA/ASIC engineering workflows, bounded tool adapters and
evidence gates. It does not include customer designs, PDKs, EDA installations,
licenses or production signoff results. An adapter or skill is an entry point;
its presence does not establish qualification on a particular target.

## Start here

1. Declare `fpga`, `asic` or `both` using [project inputs](new_project_inputs.md).
2. Use `hw-flow` to select shared work and the applicable target branch.
3. Assign architecture, implementation, independent review and orchestration to
   the four roles. Preserve the human approval boundaries in root `AGENTS.md`.
4. Bind each acceptance decision to the current source, configuration, tool and
   primary artifacts. Keep unsupported or missing evidence explicit.

## Maintained sources and generated files

| Location | Purpose | Maintenance |
|---|---|---|
| `AGENTS.md` | Project rules, target selection, approvals and evidence boundaries | Edit directly |
| `subagents/catalog.json` | Role inputs, outputs, responsibilities, handoffs, routing and aliases | Single maintained role source |
| `subagents/*.toml` | Readable role views, including compatibility names | Generated by `scripts.sync_agents` |
| `skills/*/SKILL.md` and canonical resources | Task guidance, limits and evidence requirements | Edit the maintained skill |
| `skills/manifest.json` | Skill categories, target routes, aliases and counts | Generated by `scripts/sync_skills.py` |
| `.codex/agents/`, `.claude/agents/`, OpenCode role entries | Client role adapters | Generated by `scripts.sync_agents`; unrelated OpenCode settings are preserved |
| `.agents/skills/`, `.claude/skills/` | Complete discoverable skill copies | Generated by `scripts/sync_skills.py` |
| `mcp/`, `scripts/mcp_launcher.py` | MCP services and local runtime selection | Bounded execution interfaces |
| `scripts/quality_gate/` | Shared RTL gates and selected backend checks | Manifest- and contract-driven |
| `scripts/asic_*.py` | ASIC input, execution, evidence, diagnostics and reports | CLI adapters; no ASIC MCP service |
| `schemas/`, `config/` | Data contracts, policies and reference configurations | Reference values are not project defaults |
| `templates/`, `examples/` | Starting contracts and neutral execution examples | Fill and verify for the actual project |
| `tests/`, `.github/workflows/` | Software regressions and source/configuration checks | Do not constitute EDA or hardware qualification |

Local `projects/`, generated runs, caches and private evidence are outside the
public source profile. Keep them outside commits. The release audit checks Git
publish candidates, including untracked source, and independently checks prepared
exports. See [release preparation](release_preparation.md) for the exact scope.

## Four shared responsibilities

| Canonical role | Compatibility name | Responsibility |
|---|---|---|
| `architect-hw` | `architect-fpga` | Interfaces, numeric behavior, clocks/resets, memory, architecture, budgets and verification plan |
| `coder-rtl` | `coder-fpga` | Implement reviewed RTL or an explicitly selected HLS component and run applicable gates |
| `reviewer-hw` | `reviewer-fpga` | Read-only review of design and primary evidence; no automatic human signoff |
| `orchestrator-hw` | `orchestrator-fpga` | Select targets, enforce dependencies, coordinate handoffs and report blocked scope |

Both targets use the same four responsibilities. Shared skills load at entry;
target skills load after intake. A client may register FPGA services for later
FPGA work without making them ASIC dependencies. `both` returns separate branches,
constraints, evidence and acceptance. A role definition does not authorize
delegation or EDA execution by itself.

```bash
python -m scripts.sync_agents --plan orchestrator-hw --target asic
python -m scripts.sync_agents --plan coder-fpga --target both
```

These commands only return routing plans; `execution_authorized` remains `false`.

## Tools and evidence limits

| Scope | Existing entry point | Evidence and limits |
|---|---|---|
| Numeric reference and comparison | python-sim MCP | Comparison for selected inputs; not automatic RTL correctness |
| RTL G0/G1/G2 | Manifest, lint/readability, directed smoke, protocols and formal policy | Contract-specific evidence; missing, skipped or inconclusive checks cannot PASS |
| Coverage | Verilator line instrumentation | Declared instrumented points; not complete functional, branch, toggle or DFT coverage |
| FPGA builds and reports | Vivado MCP and report/checkpoint adapters | Target/artifact-bound implementation evidence; not board functionality |
| Optional HLS | Vitis HLS MCP and report reader | Selected-component simulation and synthesis estimates; not final routed PPA |
| FPGA board operations | Exact-device/artifact program, capture and flash | Reviewed operation evidence; SoC preflight does not prove boot or DDR operation |
| AMD documentation | Separate amd-doc-search service | Release-specific research; no EDA execution or ASIC prerequisite |
| ASIC A01 | Backend, capability and input contracts | Input/tool/policy bindings; tool presence is not design qualification |
| ASIC A02 | Fixed Yosys/OpenROAD synthesis and STA | Aggregate area and WNS/TNS; not complete MMMC or hold signoff |
| ASIC A03 | OpenROAD physical implementation, DRC/LVS and finalization | Fixed-backend physical evidence; completion is not check acceptance |
| ASIC PPA | Activity planning and report build/verification | Corner, activity and parasitic assumptions; planning does not execute power analysis |
| ASIC A04 | Fixed ORFS/SKY130HD/GCD reproduction assessment | Reference-profile engineering acceptance; not arbitrary design/process signoff |

Synthesis and STA have distinct task guidance but share the current A02 execution
adapter. New skills do not loosen `config/asic_backend_policy.json` or its CLI
contracts. DRC/LVS localization can contain design identifiers and coordinates;
keep those artifacts in external run storage, not public reports.

## Unsupported or incomplete scope

The toolkit does not supply commercial ASIC EDA execution adapters, generic MMMC
closure, DFT/ATPG, UPF, IR/EM, memory compiler invocation, complete macro integration
or foundry-qualified tapeout signoff. Projects requiring them must identify an
external reviewed flow, owners, contracts and evidence. Shared formal policy does
not imply that every RTL/netlist equivalence problem has an available proof backend.

FPGA advanced ILA/VIO insertion, arbitrary BD reconstruction, DFX and embedded
software build limits remain as documented in [upstream adoption](fpga_upstream_adoption.md).

## Maintenance and verification

```bash
python scripts/sync_skills.py --write
python scripts/sync_skills.py --check
python -m scripts.sync_agents --write
python -m scripts.sync_agents --check
python -m ruff check scripts mcp tests
python -m unittest discover -s tests -p "test_*.py"
python scripts/public_release_audit.py
```

Checks cover aliases, target compatibility, local references, resource mirrors and
native adapters. ASIC routing rejects FPGA-only skills/services; reviewers remain
read-only. Unknown skill files are preserved and reported rather than deleted.
Role synchronization preserves unmanaged OpenCode roles and non-role settings.
Do not force-add ignored engineering data or weaken audit rules to obtain a PASS.

For Codex, read-only reviewer behavior is a role contract. Permissions and MCP
servers are inherited from the parent, so enforce independent review through a
read-only parent session and approved read-only MCP tools. Agent-local sandbox
or MCP overrides do not create isolation. The generated reviewer disables
supported permission-escalation, app and plugin capabilities. See the
[official custom-agent permission model](https://learn.chatgpt.com/docs/agent-configuration/subagents).
