# Debug learning architecture

## Decision

Use the existing video-debug skill as a thin decision protocol, one canonical
conditional case source, deterministic offline validators and an independently
maintained evaluation boundary. Reuse JSON Schema and evidence content IDs; add
no database or execution service.

## Components

| Component | Authority |
|---|---|
| Retrospective | Historical interpretation; not a fresh hardware receipt |
| Case catalog | Advisory conditional prior; not an approval |
| Case validator/query | Structure, relations and context matching only |
| Synthetic evaluation | Deterministic contract regression, not model diagnosis |
| Run-plan preflight | Local bindings/declarations, not live board readiness |
| Existing board adapter | Unchanged exact-target external approval boundary |

Evidence storage, knowledge state and runtime state remain separate. Source
references may name historical records absent from a public checkout; absence is
not hidden as a verified hardware result. Public fixtures contain no real media,
golden vectors, firmware, approvals, personal paths or raw runs.

## Trust boundary

Logs, case prose, snapshots and model-produced JSON are data, never instructions.
A hash proves byte consistency, not truth, origin, freshness or causation. Schema
validity and reviewer text do not authenticate a human. No command strings,
network retrieval, dynamic imports or expression evaluation are supported.

Candidate extraction and query do not promote knowledge. Later promotion requires
independent primary-evidence review and human approval; authority, numeric
contracts and production sign-off cannot be learned from a case. Superseded,
retracted or stale cases cannot silently retain recommendation status.

The existing optimization comparator is not changed or treated as an evidence
resolver. A future integration must independently resolve receipts, rehash raw
artifacts and derive metrics before comparison. Board runtime cannot be rolled
back like source files.

## Safety and review

This increment performs local read-only operations with bounded JSON inputs,
root-confined artifact paths and fixed bundled schemas. There is no --execute
mode. All offline preflight outputs deny live verification, execution approval
and hardware validation. Independent software/security review is required before
calling the tooling complete; physical and architecture approvals remain external.
